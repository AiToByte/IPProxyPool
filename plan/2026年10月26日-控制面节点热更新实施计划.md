# 控制面节点热更新实施计划（步骤 52）

> 日期：2026-10-26
> 上游依据：`docs/CAPABILITY-AUDIT.md` §4「已明确的缺失」与 §8 路线建议第 1 条
> ——「控制面 API + 配置热更新，解锁运维可运维性（当前最大短板）」。

## 1. 目标

让运维**不重启网关**即可增删上游代理节点，且变更**在进程重启后仍然存在**。

验收口径（可执行）：

1. `POST /api/v1/nodes` 新增节点后，下一次选路立即可命中（`GET /api/v1/nodes` 可见）。
2. `DELETE /api/v1/nodes/{addr}` 删除后，节点从池中消失，粘滞会话自动迁移
   （`select_node` 的 `still_live` 复核已覆盖，不需额外清理会话表）。
3. 重启进程后，增删结果仍在（磁盘文件为持久化载体）。
4. 非法输入（坏 IP、保留 provider、越界权重等）**必须**返回 `400` 与文档 §4 的
   JSON 错误体，绝不静默落库。
5. 落盘失败时**不得**只改内存：接口返回 `500`，内存与磁盘保持一致（先落盘后生效）。

## 2. 非目标（明确不做，避免范围蔓延）

- `PUT /nodes/{addr}` 全量更新、节点改名/改地址（删了重加即可）。
- 运行中**手工编辑** `nodes.json` 的热加载（文件是控制面 API 的持久化载体；
  手工编辑只在进程停止时受支持，启动时读取一次）。
- 多实例之间的节点表同步（各实例各持一份文件；跨实例一致性另行立项）。
- 免费池节点的增删（`free-*` 由 FreePool 自动供给，控制面拒绝操作并说明理由）。
- 认证/权限模型升级（沿用 `X-Admin-Key`）。

## 3. 现状取证

| 事实 | 证据 |
| --- | --- |
| 初始节点硬编码 3 个 mock（127.0.0.1:8888/8889/8890） | `gateway/src/main.rs` 的 `initial_nodes` |
| 无公开运行时注入 API | `TEST_POOL_NODES` 注释自述「没有运行时注入节点的公开 API」；`RouterEngine::reload_nodes` 带 `#[allow(dead_code)]` |
| 池写入无序列化，存在读-改-写丢更新窗口 | `replace_vendor_nodes` / `adjust_vendor_weight` / `set_paid_weight_boost` 均为 `load → 构造 → store`，互不互斥 |
| Windows 网关约 305~308s 自行退出 | `main.rs` 的 OPT-R14 注释；纯内存变更会随进程消失，因此**持久化不是可选项** |
| Admin API 已具备认证/超时/审计 | 步骤 49 落地；本次沿用同一安全边界 |

## 4. 架构

```text
                 ┌──────────────────────────────┐
  POST/DELETE ──▶│ NodeRegistry（新模块）        │
                 │  · 校验（IP/端口/tier/...）   │
                 │  · 托管节点清单（Mutex）      │
                 │  · 原子落盘 data/nodes.json   │
                 └──────────────┬───────────────┘
                                │ apply（同步）
                                ▼
                 ┌──────────────────────────────┐
                 │ RouterEngine                 │
                 │  · write_lock 串行化所有池写  │
                 │  · add_node / remove_node     │
                 │  · 与 FreePool merge 共用锁   │
                 └──────────────────────────────┘
```

### 4.1 持久化语义

- 环境变量 `NODES_FILE`：
  - 未设置 ⇒ 默认 `data/nodes.json`；
  - 设为空字符串 ⇒ **关闭持久化**（仅内存，供一次性/测试场景，文档明确标注）；
  - 设为路径 ⇒ 使用该路径。
- 启动时：
  - 文件存在 ⇒ **以文件为准**（不再注入硬编码 seeds），解析/校验失败 ⇒ 启动失败
    （配置损坏属误配，fail-closed；日志给出文件路径与具体字段）。
  - 文件不存在 ⇒ 使用硬编码 seeds，**首次增删时才创建文件**（不主动写盘，
    保持现有 clone 即用的行为）。
- `TEST_POOL_NODES` 注入的节点**不写入**文件（测试通道，进程即弃）。
- 免费池 `free-*` 节点**不写入**文件（由 FreePool 每轮 merge 重建）。

### 4.2 写入顺序与回滚

```text
校验 → 写临时文件 + fsync → rename 原子替换 → 应用到 RouterEngine → 更新内存清单
                                                  └─ 失败 ⇒ 把旧清单重新落盘（回滚）并返回 500
```

- 先落盘再应用：避免“接口 500 但内存已变”。
- 应用失败的回滚是 best-effort；若回滚落盘也失败，日志 `error!` 记录
  “磁盘与内存可能不一致”，接口仍返回 500 —— **不谎报成功**。
- 文件权限：Unix 下 `0600`（文件含上游代理凭据）；Windows 无等价位，文档警示。

### 4.3 与免费池/自动调权的边界

- `RouterEngine` 新增 `write_lock`，**所有**池写入（`reload_nodes`、
  `replace_vendor_nodes`、`adjust_vendor_weight`、`set_paid_weight_boost`、
  `scale_vendor_weights`、`add_node`、`remove_node`）共用，消除已有的丢更新窗口。
- 锁序固定为 `NodeRegistry → RouterEngine`；FreePool 只拿 RouterEngine 锁，永不拿
  registry 锁 ⇒ 无环、无死锁。
- 管理面显式调权（PATCH weight）对**托管节点**同步落盘（运维意图要持久）；
  自动调权/免费池因子（运行时策略）**不落盘**（重启回到基准，符合语义）。

### 4.4 API 契约

| 方法 | 路径 | 成功 | 失败 |
| --- | --- | --- | --- |
| POST | `/api/v1/nodes` | `201` + `NodeView` | `400` 校验失败 / `409` 地址已存在 / `500` 落盘失败 |
| DELETE | `/api/v1/nodes/{addr}` | `200` + `{"addr","removed":true}` | `404` 不存在 / `409` 非托管节点（`free-*` 或测试注入）/ `500` 落盘失败 |

请求体（POST）：

```json
{
  "ip": "203.0.113.10",
  "port": 8080,
  "country": "us",
  "tier": "residential",
  "provider": "vendor-a",
  "weight": 100,
  "proto": "http",
  "username": "optional",
  "password": "optional"
}
```

校验规则：

- `ip`：仅 IPv4（`ProxyNode.addr` 为 `ip:port` 字符串，IPv6 会产生歧义；本条如实拒绝并说明）。
- `port`：`1..=65535`。
- `country`：2 个 ASCII 字母，统一大写。
- `tier`：`datacenter | residential | mobile`（`free` 由免费池专属，控制面拒绝）。
- `provider`：非空、≤64 字节、不得以 `free-` 开头（否则会被下轮 merge 静默洗掉）、
  不得含控制字符。
- `weight`：`0..=100`（0 = 摘除；与文档“100 满权”一致）。
- 凭据：用户名/密码必须成对出现；用户名 ≤256、密码 ≤512；响应**永不回显**。
- `proto`：`http | socks5 | socks4`，缺省 `http`。
- 托管节点上限 10000（防误操作把内存打爆）。

## 7. 风险与处置

| 风险 | 处置 |
| --- | --- |
| Windows `rename` 覆盖语义差异 | Rust `fs::rename` 在 Windows 用 `MOVEFILE_REPLACE_EXISTING`；落盘测试覆盖“覆盖已有文件” |
| async handler 里做阻塞磁盘 I/O | 管理面低 QPS、单文件 KB 级；同步短临界区，避免跨 await 持锁（贡献指南禁区）。文档注明 |
| 文件含上游凭据 | Unix `0600`；`.gitignore` 已忽略 `data/`；文档警示“不要提交/外发” |
| 手改文件与内存不一致 | 明确“API 是唯一支持的在运行写入口；手改须停机” |
| 与 FreePool 并发丢更新 | 全池写共用 `write_lock`；并发回归测试锁死 |
