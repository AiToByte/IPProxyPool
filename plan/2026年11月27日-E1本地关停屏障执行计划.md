# IPProxyPool 后续生产可信化工作

## 本轮目标与状态

继续 T1 生产可信化，不进入 T2/T3/T4。当前本地工作项聚焦可复现的关停屏障：先关闭 admission，再等待数据面结算完成；停止并确认周期租户 flusher 已退出后，才做有界 final flush。不能把本地状态测试当成 Linux/Pingora 端到端关停证明。

用户本机基础使用链路已由 `docs/USAGE.md` 支持：启用 `FREE_ENABLED=1`，监控免费池水位，客户端请求打到本地 Gateway、将真实目标放入 `Host`；标准 HTTP proxy 形态可通过 `tools/ipp_forward.py` 翻译。公开免费代理可能为空，空池返回 503；前置适配器不转发 CONNECT。

## 已完成事实

- 本轮新增的关停测试已在实现前记录 RED：在对 flusher 的 `JoinHandle` 做超时等待时，3 个测试观察到 join timeout 后任务仍存活、signal watcher future 取消时后台任务脱离、final flush 并不能证明上一个 flusher 已终止。输出保留于本机 `log/e1-shutdown-red.log`（仅本地验证记录）。
- HTTP 租户上下文取消行为已记录 RED：释放 admission 后仍有 `in_flight=1`，已观测 512 字节未结算。原因是正常 HTTP 结算只在 Pingora `logging()` callback。
- CONNECT 已存在 `SettlementGuard`，其声明位置先于 lifecycle admission，析构顺序使 settlement 先于 quiescence 通知；为此增加测试断言：取消后 quiescence 前仍有 admission，quiescence 完成时 tenant slot/bytes 已结算。
- `RuntimeHealthState::wait_for_quiescence` 只覆盖取得 lifecycle `AdmissionLease` 的 HTTP/CONNECT 数据面；Admin PATCH tenant balance/active 没有纳入该 admission。因此 final flush 与并发管理写入可能有竞争，必须保留为 completeness 限制，除非本轮另行实现并测试 Admin drain/write barrier。
- 周期 flusher abort/本地 join 仅说明当前进程的 async task 已结束，不意味着 Redis 已撤销一个已发送命令。Final flush 是 best-effort，不作为远端 exactly-once/无副作用保证。

## 本轮实现进度

- `gateway/src/shutdown.rs`：抽出 watcher 中 drain → stop-broadcast → quiescence → flusher stop/join → final flush 编排；shutdown report 只有 quiesced、flusher 正常 join（或未运行）、final flush 成功三项同时满足才报告 local complete。
- `gateway/src/shutdown/tests.rs`：加入有界 join、watcher future 取消、drain timeout、flush failure/timeout 和 flusher panic 的受控回归。
- `gateway/src/tenant.rs`、`gateway/src/model.rs`、`gateway/src/gateway/hooks.rs`：拟以 request-owned `TenantSettlement` RAII guard 承载租户并发槽和累计字节，Drop 在 admission lease 释放前结算；正常 logging 将 guard 显式结算以保留实际节点 tier 的计价；重试需同步重置 guard 字节。
- `gateway/src/connect.rs`：补 quiescence 与 tunnel settlement 顺序的行为断言。

以上是本轮进行中的实现，不代表已通过 GREEN 或 review；须先修复构建/行为问题并跑完整验证后再升级为已验证。

## 关键风险与未关闭边界

1. **flusher 任务停止超时**：必须 abort 并再有界 join；仍无法确认结束时跳过 final flush，并报告 incomplete，不可让两个写任务并行。Tokio `abort()` 不回滚已发送到 Redis 的命令。
2. **flusher watcher 取消**：RAII 持有 stop sender 与 JoinHandle；Drop 需尽可能发送 stop 并 abort，避免 detached task。Drop 中无法 await，所以 cancelled watcher 仍不能声明 join 成功。
3. **租户结算 ownership**：HTTP 正常、retry 清零、SOCKS bridge body、错误和取消必须各自只结算一次；guard 必须在 AdmissionLease 前析构。未观察到的响应字节不能结算，但已由回调看到的字节应被保留。
4. **Admin API 并发更新**：当前 admission/quiescence 不含 Admin tenant PATCH。除非增加并验证其 drain/写屏障，否则完整性声明需要明确排除此路径，不能只看 `flush_dirty() -> Ok(n)`。
5. **Pingora/runtime 同步**：watcher 与 Pingora runtime/service teardown 的同步关系尚未由本地单测证明。SIGTERM/Ctrl-C、listener teardown、所有回调结束与 process exit 仍须按当前 revision 在隔离 Linux 环境核验。
6. **外部证据**：真实 Redis write/response 取消语义、当前 Linux live SIGTERM、Ctrl-C、容量/SLO、alert receiver、canary/rollback 仍是独立门禁；不可用则标注 BLOCKED/NOT RUN。不要使用或持久化服务器口令。
7. **免费代理**：公网来源可用性、授权和目标兼容性不受本项目保证；`free_pool_nodes_total=0` 时本闭环的 `tier=free` 请求应返回 503。
