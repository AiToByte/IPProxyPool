# Phase 5 韧性验证 Implementation Plan（2026年9月22日）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Goal:** 用真实断电演练验证三条从未 E2E 走过的降级/恢复路径——Redis 中断、
> ClickHouse 中断、Mock 全/半中断。预期全部自愈、无 panic、无 OOM、无静默丢数；
> 演练暴露的真 bug 按 P0 修（本计划预留修复位），无 bug 则零代码变更交付。
>
> **Architecture:** 演练即断言（无新模块）：`docker stop/start` 逐个断依赖 →
> 数据面 curl 断言（200/503 按场景）→ 指标断言（dropped/landed/XLEN/CH 行数）→
> 恢复断言（行数追齐＋PID 不变＋日志无 panic）→ 落库。
>
> **Tech Stack:** 现状复用（docker compose 服务名 redis/clickhouse；网关 detached 二进制；
> mocks 复用 `log/mock_upstream.py`）。
>
> **Deviations locked（勘察结论，以本节为准）：**
> - F1 · CB 内存隔离不依赖 Redis（`apply_quarantine` 步骤 1 先写内存，2/3 才碰 Redis，
>   且皆 `unwrap_or(())`）——Redis 中断期间隔离语义不降级，演练只验不断言降级。
> - F2 · telemetry 中断语义：flush 失败→100ms 重发→仍失败整批 dropped 计数（OPT-4）；
>   若 ConnectionManager 重连阻塞 flush，mpsc 满后走 `channel_dropped`——断言两者之和
>   增量 >0（不预设单一口径，诚实）。
> - F3 · sink 中断语义：insert 失败 hold ack＋backoff，内存以 `rows_cap` 为界（R2-5）；
>   XLEN 不因子 ack 缩（Stream 长度只增），故恢复断言看 CH 行数追齐＋`landed` 日志，
>   不看 XLEN 缩。
> - F4 · mock 全挂→503（`upstream_peer` 无候选）；connect 失败不进 quarantine
>   （隔离只消费上游响应状态），故重启后立即 200，无需等 TTL——若出现需等 TTL 才恢复，
>   即记 P0 回归。
> - 演练期间 FREE 默认关闭（免费 tick 为外部变量，隔离演练噪声；免费线韧性由 TTL/hold
>   语义覆盖，既有 E2E 已验）。
>

## §4. bug 修复位

### BUG-5-1（P0，已修）：hold-and-redeliver 撞 SeenIds 去重窗致 CH 中断恢复后静默丢数
- **现象**：P5-2 首轮：CH 中断期 10 流量→`insert failed holding acks`→CH 重启＋90s 后
  pending 归零、CH 行数静止（3390→3390）、无 `landed` 行——10 行静默丢失。
- **根因**：`classify_entry` 首读即把 event_id 记入 SeenIds；hold 的条目被 autoclaim
  取回（同 stream id 重现）时再次走去重检查→误判重复→skip＋ack。去重窗本为对消
  “重试新条目”（不同 stream id），不适用于同 id 重放。
- **修复**：`classify_entry` 加 `is_redelivery` 形参（reclaim 路径传 true 直通 rows，
  fresh 路径传 false 保持去重；调用点 2＋单测 5 处同步）；`too_many_arguments` 沿
  `ProxyNode::new` 惯例放行。
- **单测**：`redelivered_hold_is_not_a_duplicate`（首读有效→重放仍有效→重试新条目仍去重）；
  R2-5 三单测语义不变全绿。
- **复验**：同条件重演→`landed 4＋6` 行、CH 3390→3400（+10 全追回）、pending 归零。
  （原“保持为空”预期作废，以本条为准。）
