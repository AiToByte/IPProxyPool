# OPT-R13 方案：LinUCB 永久锁死修复（恢复 anytime 性质）

> **来源:** OPT-R11 真实网关回归中实测到的现象——无约束 60 次请求 60/60 命中同一节点；经 pre-B1/B1 双二进制 A/B 证明**与选路重构无关**，根因在 bandit 打分本身。
> **性质:** 算法语义变更。故本轮**先量化根因、再 A/B 候选修法、最后才实施**，且每个候选都用仿真证伪或证实，不靠直觉。

---

## 0. 根因（已用数值仿真复现，非推断）

打分算式（`bandit.rs::compute_ucb_score`）：

```
score = expected_reward + alpha*variance - 0.05*cost_weight
  expected_reward = (A⁻¹b)·x      # ridge 估计
  variance        = sqrt(x'A⁻¹x)   # 置信椭圆半径
  alpha           = 0.4
```

复现 2000 步选路（`d=4`，`A⁻¹=I`，`b=0`，reward 0.99，domain_risk 0.3）：

| 臂 | pulls | expected_reward | variance | score |
| -- | ----- | --------------- | -------- | ----- |
| mock-a (res, cost 1.0) | 0 | 0.000 | 1.459 | 0.534 |
| mock-b (dc, cost 0.1) | 2000 | **3.978** | **0.045** | **3.991** |
| mock-c (mobile, cost 3.0) | 0 | 0.000 | 1.459 | 0.434 |

分布 `{mock-a:0, mock-b:2000, mock-c:0}` —— 与活流量实测的 60/60 完全一致。

**根因是两个不等式同时成立，构成数学上的永久锁死：**

1. **利用项无上界。** `b` 随每次 update 线性增长，ridge 估计 `A⁻¹b` **没有对量级做正则**，故 `expected_reward` 可以远超 1.0（实测 3.98 且仍在涨）。而 `compute_reward` 的返回值**本身就被设计在 [0,1]**（`200..=299 => 1.0 - 延迟/2000` 上限 0.5；`403|429 => 0.0`；其余 `0.2`）——**超过 1.0 的"期望奖励"是估计量纲的数值假象，不是真实信号**。
2. **探索项有上界且递减。** `variance = sqrt(x'A⁻¹x)` 对未拉过的臂恒为 `‖x‖ ≈ 1.46`，**永不增长**；对被反复拉取的臂则随 `A⁻¹ → 0` 塌缩到 0.045。故探索加成**封顶在 `0.4×1.46 ≈ 0.58`**。

**探索有界 ＋ 利用无界 ⇒ 一旦某臂被选中，它就永远赢。** 这不是调参问题，是结构问题：当前 `variance` 形式**丢掉了 UCB 的"随全局时间增长"这一关键性质**，于是这个"bandit"不具备 anytime 性质。

## 1. 候选修法的 A/B 评估（仿真，各 2000 步）

除了"锁死是否消失"，还测 **anytime 性质**（第 500 步插入一个更优臂，看多久被发现）——这才是 bandit 存在的意义。

| 候选 | 2000 步分布 | 新优臂发现耗时 | 判定 |
| ---- | ----------- | -------------- | ---- |
| **A 现状** | b=2000 (100%) | **从未被发现** | 基线 |
| **B 仅裁剪 `expected_reward` 到 [0,1]** | b=2000 (100%) | **从未被发现** | ❌ **无效** |
| **C 探索项 × √(ln(1+t)/(1+n))** | b=1982, a=14, c=4 | **1 步**，拿到 49.5% 流量 | ✅ **有效** |
| **D = B + C** | 同 C | 1 步 | 冗余（B 无贡献） |
| **E 每 500 次遗忘**（把 `FORGET_EVERY_N_UPDATES` 调小） | b=2000 (100%) | **从未被发现** | ❌ **无效** |

**两个反直觉的证伪，值得记下来：**

- **B 无效**：因为 `1.0` 的奖励仍然压过 `0.58` 的探索上界。裁剪只把"压得更狠"变成"压得一样狠"。
- **E 无效**：遗忘把赢家拉回接近初始状态，但下一轮它又被立刻选中并重新学回 ⇒ **锁死重现**。调遗忘频率是在治标，且会丢掉"付费线不遗忘"这一既定设计意图。

**只有 C 恢复了 UCB 的标准形式。** 标准 LinUCB 的探索项是

```
c * sqrt(d * ln(t) / n_i)
```

——**随全局步数 `t` 增长、随该臂已拉次数 `n_i` 衰减**。当前代码的 `variance = sqrt(x'A⁻¹x)` 只保留了"随 `n_i` 衰减"的一半，**丢掉了"随 `t` 增长"的一半**。C 就是把缺的那一半补回去。

---

## 2. 选定修法（候选 C）

```
exploration = alpha * variance * sqrt( ln(1 + t) / (1 + n_i) )
score       = clamp(expected_reward, 0, 1) + exploration - 0.05*cost_weight
```

- `t` = 全局选路步数，`n_i` = 该臂累计 update 数（`ArmState::updates` **已存在**，无需新增 per-arm 字段）。
- `t` 需要一个全局计数器：`LinUCBEngine` 当前是**无状态**的（注释明写 "stateless; arm state lives in `BanditArm`s"），故加一个 `AtomicU64`（选择路径本就每请求一次，加一个原子自增的开销远小于已有的 `RwLock` 读）。
- `expected_reward` 裁剪到 `[0,1]`：**不是**因为它能修锁死（B 已证无效），而是因为让它符合 `compute_reward` 的真实值域、消除"3.98 这种量纲假象"对**可观测性**的误导。二者都做，但**理由必须分开写清**——否则后人会以为裁剪是修复手段而删掉它。

### 稳定性验证（仿真，3000 步）

| 场景 | 现状 | 加 C 之后 |
| ---- | ---- | --------- |
| 三臂质量相同 | 切换 0 次，b=3000 | 切换 **30** 次，b=2982，a/c 各得 14/4 |
| b 明显更优 | 切换 0 次，b=3000 | 切换 **6** 次，b=2997，a=2/c=1 |

**判读：** 最优臂仍拿 **99.4%** 流量（**探索不稀释最优**），切换 30/3000 步（≈1%，**不抖动**），同时恢复 anytime 性质。这是"恢复探索"该有的形态——**少量持续探索 ＋ 强利用**，而不是均匀轮询。

## 3. 实施要点

- **B1**：`LinUCBEngine` 加 `selections: AtomicU64`；`select_best_arm*` / 流式打分处取 `t = selections.fetch_add(1) + 1`。
  - ⚠️ 注意 `select_bandit_node_excluding` 是**单趟**打分（每个候选算一次分），计数器须**每次请求自增一次**，不能每个候选自增。实现上把 `t` 在循环外取一次传入。
- **B2**：`compute_ucb_score` 增 `t: u64` 参数（`n_i` 从 `state.updates` 读），裁剪 `expected_reward`。
- **B3**：单测——
  1. **锁死回归**：三臂（cost 0.1/1.0/3.0）、同 context、连续 2000 次打分，断言**三个臂都被选中过**（现状下只有 1 个）。
  2. **anytime**：中途加入更优臂，断言在**有界步数内**被发现。
  3. **不稀释最优**：明显最优臂长期占 **>90%** 流量（防"修探索改成轮询"）。
  4. `expected_reward` 裁剪：断言 score 计算不再出现 >1 的量纲假象。
  5. 纯函数边界：`t=0`、`n_i=0`、`ln(1+t)` 的数值稳定。
- **B4**：release bandit 门（8 臂 <200ns）**不得回归**——新增的 `ln`/`sqrt` 会改变成本，必须复测。若超标，改为预计算 `sqrt(ln(1+t))` 的增量更新或把 `ln` 移出热路径。

## 4. 验收标准

- 四门绿；`cargo test --locked --release bandit` 8 臂仍 <200ns（**硬要求**）。
- 新增 5 类单测全绿，其中"锁死回归"与"anytime"是核心。
- **活流量复验**：同样的 mocks（8888/8889/8890）＋ release 二进制，无约束 300 次请求，断言**三个 mock 都被命中**（现状是 0/300/0）。这是本轮唯一能证明"活流量下真的修好了"的证据，单测不足以替代。
- 与 pre-R13 二进制做 A/B 对照，确认**约束路径（country/tier）与鉴权 403 行为零变化**。

## 5. 明确不做

| 项 | 理由 |
| -- | ---- |
| 调大 `alpha` | 只是在有界探索项上加常数，仍无法对抗无界利用项；治标且会稀释最优臂 |
| 调小 `FORGET_EVERY_N_UPDATES` | 仿真已证无效（E），且违背"付费线不遗忘"的既定意图 |
| 改 `cost_weight` 系数 | 成本差 0.145 远小于锁死幅度（3.5），与根因无关 |
| 引入 `subtle` 等新依赖 | 与本项无关（OPT-R12 已论证不需要） |
