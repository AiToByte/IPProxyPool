## Tasks and Gates

### Task 1: Flusher stop/join

- **RED**: Add a deterministic test that starts a persistent flusher with a controlled backend, blocks an in-progress write using Notify/oneshot, sends stop, and proves the returned task does not join before the blocked write is released. After release, assert join completes and no later tick runs. Avoid fixed short-sleep assertions.
- **GREEN**: Expose a named flusher control type (or a narrow `(oneshot::Sender<()>, JoinHandle<()>)` tuple if established style favors it). In shutdown, wait for admission quiescence, signal stop, join with a bounded deadline, then final-flush. If join times out/fails, log that periodic writer may still exist; do not claim serialization is closed.
- **Mirror**: `PausedWriteBackend` in `tenant.rs`; fixed shutdown error reporting in `main.rs`.
- **Validate**: targeted flusher test, `cargo fmt`, Clippy, workspace tests.

### Task 2: Restore completeness matrix

- **RED**: Extend `RecordingBackend` to separately model the index set and hash storage. Cover empty index (first boot), full valid restore, missing configured index member, index member with missing hash, malformed hash, and orphan key. Assert no default-state record is treated as restored and no malformed key is silently declared complete.
- **GREEN**: Keep an explicit restore report with configured/applied counts, indexed keys, malformed keys, and missing configured keys. Required startup fails for incomplete non-empty persisted state. Only an empty index plus no scanned tenant records is allowed for first boot. Configured unindexed records fail closed without application; unknown records are orphan diagnostics only. Complete deletion of all state still cannot be distinguished from first boot without a durable initialization marker.
- **Startup integration**: Add a loopback RESP fixture mode that returns a non-empty index and then serves a missing/malformed hash; assert exit 1 and no flusher startup. Existing empty-index test must continue passing.
- **Validate**: tenant restore tests and `cargo test --test redis_startup`.

### Task 3: Deterministic shutdown ordering

- **RED**: Add an injected local coordinator test with event recording and held admission lease. Assert exact order: `drain_closed -> worker_stop -> quiescence -> flusher_stop -> flusher_join -> final_flush`. Cover successful drain, drain timeout, join failure/timeout, and flush failure/timeout without OS signals or sleeps.
- **GREEN**: Keep production SIGTERM watcher calling the same small ordering function or shared primitive. Preserve current bounded 5-second policies unless tests or existing config establish a different value. Explicitly report timeout as best effort.
- **Validate**: targeted shutdown sequence tests and existing `shutdown_flush_is_bounded_when_storage_hangs`.

### Task 4: Settlement before final flush

- **RED**: Controlled loopback CONNECT test establishes a tunnel, sends known bytes, holds relay completion, begins drain, and verifies quiescence/final flush cannot complete until the tunnel settlement guard drops. After releasing both peers, assert persisted bytes/balance contain the final usage. Use channels/barriers and recording backend; no sleep-based race assertions.
- **GREEN**: Adjust ownership/drop ordering only if the test exposes a real defect. Preserve relay-after-drain behavior and the shutdown-watch boundary after HTTP 200.
- **HTTP boundary**: Prove request lease covers `logging()` settlement; if Pingora offers no deterministic app hook, record that specific behavior as unproven instead of claiming it.
- **Validate**: focused CONNECT and gateway lifecycle tests.
