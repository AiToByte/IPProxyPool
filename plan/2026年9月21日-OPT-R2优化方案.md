## 拆解

### R2-1 选路正确性（router.rs + vendor_arbitrage.rs）—— P0，首执行
- 现状：`router.rs:159-172` `weight==0` 走 `retain` 删除节点，`restore→100` 只改残留节点权重，被删的找不回（单测 `vendor_arbitrage.rs:144-147` 自认 out of scope）；`select_node:132-139` 全程均匀 `choose()`，`weight` 从未参与选择。
- 改法：
  1. `ProxyNode.weight==0` 视为“摘除”，保留在池内，`get_healthy_candidates/select_node` 过滤 `weight==0`，`snapshot_all` 仍返回全量（修剪白名单语义不变）；
  2. `select_node` 改加权随机（累积权重，二分查；权重全 0/全等价时退化均匀，保证存量单测绿）；
  3. `adjust_vendor_weight` 只改数字不增删；`arbitrage_action` 阈值 `<80→0 / >95→100 / else hold` 不变；
  4. 套利恢复路径可测：derate→候选为 0（该 vendor×country）→restore→候选回来。
- 单测：`derate_hold_restore_cycle`（3 节点池，cut→hold→restore 全周期）、`weighted_distribution_skew`（权重 1:9 大样本偏斜不断言精确值只断言方向）、存量 `sticky/quarantine/sweep` 全绿。
- 回滚：单文件 `router.rs` 回退即回均匀随机（行为降级但可用）。

### R2-2 重试换节点 + 会话隔离 + Host 归一（gateway.rs + router.rs + model.rs）—— P0/P2
- 现状：`gateway.rs:232-255` 重试不换节点；`router.rs:119-128` 会话 key 只有 `session_id` 跨租户串扰；`gateway.rs:340-350` + `router.rs:71-76` Host 未归一化（大小写/端口可绕隔离），缺 Host 默认 `""`。
- 改法：
  1. `ProxyContext` 加 `last_failed_addr: Option<String>`（或复用 `current_node`），`fail_to_connect` 记录失败 `addr`，`upstream_peer` 选路时排除该 addr（单次重试内），3 次耗尽仍 503；
  2. 会话 key 改 `{tenant}:{session}`（租户缺省为 `default`，存量单测 key 无前缀的走兼容：无租户时沿用裸 key，见代码注释）；
  3. `normalize_domain(host)`：小写 + 剥端口 + 去尾点，`parse_routing_spec` 与 `is_quarantined/set_quarantine` 统一入口；缺 Host → `request_filter` 直接 400（Pingora 层先于选路）。
- 单测：重试排除、跨租户不串、归一化三组纯函数单测；curl 需多节点池验证（单节点池重试仍 503 属正确）。
- 已知限制：Pingora 重试是否重调 `upstream_peer` 以版本实测为准，走查 + 日志确认。

### R2-3 租户计费门（tenant.rs）—— P0
- 现状：`tenant.rs:104-126` 无余额门禁（可负无穷）、`register_tenant:72` burst=1 误杀突发、`api_key` 明文存 key。
- 改法：
  1. `authenticate_and_throttle` 加 `balance_usd > 0` 门（余额≤0 判 402/403，错误文案与 403 区分，网关映射状态码同步改）；
  2. `register_tenant` 加 `burst: u32` 参数（默认 `qps/10 max(1)`），`Quota::per_second(qps).allow_burst(...)`，存量调用点（main + 单测）同步改；
  3. 明文 key 本轮不做哈希（ out：GW-R3 换 SecretStr + 常量时间比较，此处记延后）。
- 单测：透支拦截、burst 突发通过、计量扣减三组；curl 坏 Key 403 / 超限 429 语义不变。

### R2-4 遥测语义（telemetry.rs + metrics.rs + gateway.rs + main.rs）—— P0/P1
- 现状：`telemetry.rs:142-170` 重试 `XADD *` 重复落库、`batch_len` 含 JSON 失败虚高；`emit:67-72` channel-full 丢弃无计数；`main.rs:200-203` 降级仍构造 Event 浪费。
- 改法：
  1. Event 加 `event_id`（`{unix_ms}-{seq}`，网关侧 `AtomicU64` 发号），`XADD {event_id} ...` 显式 ID，重试同 ID 幂等；sink 侧加已见 ID 去重窗（LRU 10k，见 R2-5）；
  2. 双计数器：`channel_dropped`（emit 满队列）+ `flush_dropped`（现有），`metrics` 渲染两行，存量 `telemetry_dropped_total` 语义冻结为 flush 口径，新增 `telemetry_channel_dropped_total`；
  3. 降级模式 `main` 置 `telemetry=None`（跳过 Event 构造），`logging` 已是 `Option` 分支零改动；
  4. `run` 的 `sleep` 改 `interval` ticker（低 QPS 延迟稳定 100ms）。
- 单测：ID 幂等（同 ID 两次 XADD 只一例行——live）、双计数器 render、降级分支走查；日常以 clippy + 走查为准。

### R2-5 CH Sink 背压（ch_sink.rs + telemetry.rs + deploy）—— P0/P2
- 现状：`ch_sink.rs:64-154` CH 宕机时 reclaim+新读叠加内存无限涨；毒丸与有效混批时宕机连毒丸也不 ack；`sink_{pid}` 幽灵消费者残留；Stream 无 MAXLEN。
- 改法：
  1. `pump_once` 失败 fast-return（不累积），`rows` 加上限（如 2×batch，超限截断 + warn + 下轮再捞）；
  2. 毒丸单独先 ack（分 `poison_ids` / `valid_ids` 两批，毒丸即时 ack，有效按 insert 成败 ack）；
  3. 启动时 `XGROUP DELCONSUMER` 清 60s+ idle 的死消费者（或后台 10min 一次）；
  4. `telemetry.rs flush` 的 `XADD` 加 `MAXLEN ~100k`（`xadd_maxlen`），CB/sink 挂了 Redis 不爆；
  5. R2-4 的 `event_id` 去重窗落 sink（`HashSet` 环形 10k，命中即 ack+skip）。
- 验收：live（CH 停启）无 OOM、无重复行；单测纯毒丸批推进；`XLEN` 有界。

### R2-6 数据面性能（router.rs + metrics.rs + bandit.rs + model.rs）—— P1
- 现状：每请求克隆全池 String（R2-1 顺带改）；`metrics.rs:67-91` 10 原子 + 正序桶撕裂单调性；`bandit.rs:120-122` context 算两次（含 syscall）；`update:98-105` 永不遗忘探索归零；`domain_risk:147-156` 硬编码 4 家。
- 改法：
  1. 池存 `Arc<ProxyNode>`（R2-1 一并落地），`ProxyNode` 预存 `addr`，候选返回 `Arc` 引用零克隆；
  2. 直方图写侧单原子（只加首个匹配桶），读侧累加渲染，根治撕裂；
  3. `ProxyContext` 存 `bandit_context: Option<VectorD>`，`upstream_peer` 计算一次，`logging` 复用（消除二次 syscall + 选学一致）；
  4. 遗忘第一步：`update` 加 `decay`（`A_inv *= 0.999` / `b *= 0.999` 可配常量，本轮保守小值）或每 10k 次 update 轻 reset（选其一，单测锁定行为）；
  5. `domain_risk` 抽配置表（本轮只加 perimeterx/kasada/imperva 三条，不做大表）。
- 验收：`cargo test --release bandit` 8 臂仍 <200ns；直方图单调性单测；存量 bandit 7 单测绿。

### R2-7 后台并发控制（prober.rs + pool.rs + router.rs + main.rs）—— P1
- 现状：`main.rs:207-240` prober 串行（百节点堵死 ticker）；`prober.rs:60-76` Client 永不淘汰（含明文账密 key）；`pool.rs:59-104` 票据环空转 + 建链无上限 FD burst；三 ticker 同 60s 惊群。
- 改法：
  1. Prober 改 `JoinSet` + 信号量 20，`TRACE_URL` 加备用（`example.com`/`google` quorum 2/3，本轮先双 URL 降级不断言细节）；
  2. `clients` 加 TTL 淘汰（复用 R2-1 sweep 节拍，`last_used` 超 10min 删）或 LRU（选 TTL，改动小）；
  3. `proxy_url_for` 账密百分号编码；
  4. Prewarmer 建链加信号量 100，票据环删除（只留真 TCP 探测 + 日志），`WarmStats.tickets` 语义冻结为探测节点数（OPERATION 更新一行）；
  5. 三 ticker 加 jitter（`60s + rand(0..5s)`，启动错峰）。
- 单测：淘汰、编码、限流（本地 listener + 拒连端口沿用 OPT-6 手法）；日志对齐验证。

### R2-8 运维安全收尾（main.rs + metrics.rs + gateway.rs + docs）—— P2
- 现状：`main.rs:46-53` 配置硬编码；后台裸 `spawn` 无 supervisor；`metrics.rs:169-208` 无读超时/并发上限；缺 Host 默认放行；每请求 `info!` + 明文 IP。
- 改法：
  1. `REDIS_URL/CLICKHOUSE_*/PORTS/INTERVALS` 全 env 化（`REDIS_URL/CLICKHOUSE_URL/.../GATEWAY_ADDR/METRICS_ADDR`，缺省沿用现常量，compose 示例同步）；
  2. 后台任务包 supervisor（`loop { run(); backoff }` + panic 计数进 metrics，本轮先包 CB/sink/arbitrage 三个）；
  3. metrics 加读超时 5s + 单连接 body 上限（现有 1024 保留）+ 并发上限说明（本轮不引新依赖，超限即关）；
  4. 缺 Host 400（R2-2 落地，此处 OPERATION 记一行）；
  5. 数据面日志降 `debug!` + 错误采样（`status>=500` 全量，其余 1/1000，计数器可观测）。
- 验收：curl 缺 Host 400、/metrics 200、后台 kill -9 工人后自愈（走查）；OPERATION §4/§6 更新。
