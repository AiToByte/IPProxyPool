# OPT-R11 优化方案：残留 P0 崩溃根治＋选路零物化＋隔离表水位

> **来源:** OPT-R10 审阅后的全量深审（`gateway/src` 20 文件 181 处 `unwrap/expect/panic` 逐点分类；11 个 `DashMap` 插入点逐个回溯 key 来源）。
> **本轮所有断言已逐条实证**（下文每项均附"已核实"的行号与代码；不采信转述）。
> **优先级:** A 组 P0 崩溃（数据面 panic）→ B 组 P1 性能 → C 组 P1 资源。
> **原则:** 存量行为零变化；每项独立可回滚；先红测后实现；注释中文为主。

---

## 0. 勘察结论（决定本轮范围的三件事）

1. **OPT-R6 S2 漏了一处 P0。** `janitor.rs` 的文档注释自述修的是"三处"
   （`sweep_expired_at` / `evict_idle` / `evict_idle_clients_older_than`），
   但 `gateway.rs:247` 的 `prune_stale_arms` 是**第 4 处同构写法**，且
   `arms` 正是数据面 `arm_for()`（`gateway.rs:85`）并发 `insert` 的同一张表。
   —— 这类"单一真源只收编了 3/4"的漏网，是比新 bug 更值得记的教训。

2. **`metrics.rs` 没有第二个无界 key。** 13 个 `DashMap` 的插入点全部回溯到
   key 来源：除已加 `EXIT_LABEL_CAP=512` 的 `free_exit_total` 外，其余均为
   字面量或经 `free_pool.rs` `intern_name` 固化的 `&'static str`，基数被
   `config.api_urls/html_urls/github_urls` 长度钉死。
   **但真正的无界 key 在 `metrics.rs` 之外**（见 C1）。

3. **鉴权不存在"时序攻击"问题。** `tenant.rs:119` 用 `DashMap::get()` 哈希查找，
   比裸 `String ==` 安全（攻击者须先猜中 SipHash 才有 key 比较）。
   故**不把"加常量时间比较"列为本轮项**——那会制造一个不存在的威胁模型。
   真正问题是 `default_key` 策略，属行为变更，见 §5。

## A 组（P0，数据面 panic）

### A1 `prune_stale_arms` 计数下溢（P0，第 4 处漏网）

**已核实** `gateway.rs:239-248`：

```rust
pub fn prune_stale_arms(arms: &DashMap<String, Arc<BanditArm>>, router: &RouterEngine) -> usize {
    let alive: std::collections::HashSet<String> = router.snapshot_all().iter().map(|n| n.addr.clone()).collect();
    let before = arms.len();
    arms.retain(|key, _| alive.contains(key));
    before - arms.len()          // ← 第 247 行：并发生长即下溢
}
```

**危害：** 后台 sweep 每 60s 调一次（`main.rs:808`）。两次 `len()` 之间若数据面
`arm_for()` 插入新臂 ⇒ `after > before` ⇒ debug **panic**（sweep 任务死亡，
靠 `supervise_until` 退避重启 + `supervisor_restarts_total{worker="sweep"}`
计数兜底，附带 1s 空转）；release **回绕成 `usize::MAX`**，再经
`main.rs:810` 的二次溢出，日志永久输出天文数字。

**修法:** 改用已存在且已有单测锁定三态语义的 `janitor::removed_count(before, after)`。
**行为零变化**（纯删除时与普通减法逐值等价，见 `janitor.rs:90` 的穷举测试）。

**同时修文档债:** `janitor.rs:6-8` 与 `:45` 的"三处"改为"四处"并列出第 4 处，
否则下一个人还会漏。

**红测:** 构造并发增长场景（`before` 采样后插入）断言不 panic 且返回 0。
**验收:** `cargo test` 绿；debug 下构造并发窗口实测无 panic。

### A2 SOCKS 总预算 `Instant` 加法溢出 panic（P0）

**已核实** `gateway.rs:437`：

```rust
let deadline = std::time::Instant::now() + socks_overall_budget(attempts, bridge.timeout());
```

`socks_overall_budget`（`gateway.rs:308-310`）只做 `saturating_add(8s)`，
**不封顶**；`bridge.timeout()` 来自 `main.rs:772` 的
`env_secs("SOCKS_BRIDGE_TIMEOUT_SECS", 20)`，而 `env_secs`（`main.rs:144-151`）
**无上限过滤**。传一个接近 `u64::MAX` 的秒值即 `Instant` 加法溢出 panic。

**危害:** 数据面 panic。触发只需**一个 env**（`SOCKS_BRIDGE_TIMEOUT_SECS`）+
一个带 `X-Proxy-Proto: socks5` 的请求，无需任何权限。这比 A1 更易触发
（A1 要撞上 60s 窗口内的并发窗口）。

**这是本仓第 4 处同类防护的漏网**，已有三处先例：`router.rs:156` `checked_add`、
`main.rs:155` `clamp_free_ttl`（30 天上限）、`gateway.rs:428` `saturating_add`。
故本仓的既定做法是**上限钳制**（`clamp_free_ttl` 的注释明确写"非法大值即 panic"）。

**修法:** 仿 `clamp_free_ttl` 加 `clamp_bridge_timeout()`，上限取
`QUARANTINE_MAX_TTL_SECS`（86400s=1 天）同量级——远高于任何合理值，行为无变化。
在 `env_secs` 读入处钳制（单一入口，避免多处防漏）。

**红测:** 断言 `clamp_bridge_timeout(Duration::from_secs(u64::MAX))` 不溢出，
且实测 `Instant::now() + clamp(...)` 不 panic（先证明未钳制版本**会** panic）。

## B 组（P1，选路热路径 O(N) 物化）

### B1 每请求两次 O(N) `Vec` 重建（本轮最大性能收益）

**已核实**——无状态请求一轮里物化**两次**全量候选：

1. `router.rs:303-324` `get_healthy_candidates_excluding` → `Vec<Arc<ProxyNode>>`
   （`router.rs:399-404` `select_node_excluding` 第二步**又来一次**）
2. `gateway.rs:333-336` `select_bandit_node_excluding` → `Vec<Arc<BanditArm>>`

**代价**（`FREE_MAX_NODES=2000` 缺省）：每请求约 2KB + 16KB 分配
+ 约 11 次 realloc（`candidates.iter()` 的 `size_hint` 下界为 0，`collect`
走倍增策略），外加 N 次原子引用计数递增（`.cloned()`）。而最终**只用到一个元素**。

**关键论证（已核实，修法形态据此确定）:**

- `pick_weighted`（`router.rs:516-536`）只需 `total`（权重和）＋ 一次 roll ＋
  一次扫描，**天然可流式**。改法：两趟遍历同一 `ArcSwap` guard（不物化），
  分配量 O(N) → 0。`total == 0` 的均匀退化分支需先数出 count、再按 index 取，
  同样是两趟、零分配。
- `select_best_arm`（`bandit.rs:178-193`）**已核实是单趟打分、只保留最优引用**，
  不需要看到全量切片 ⇒ **bandit 侧那一次物化同样可免**。改为流式：遍历候选
  → 逐个 `arm_for`（`get()` 短生命周期 ref，**不跨调用持有**）→ 打分 →
  只保留最优的 `(节点, 臂)` 一对。
- **顺带消掉一次 O(N) 复查。** 现实现是先在 `arms` 上选出 `best.key`，再
  `candidates.iter().find(|n| n.addr == best.key)`（`gateway.rs:338`）**二次扫描**
  找回节点。流式版在打分时同步记录节点，臂键即 `addr`（`gateway.rs:78`
  冷路径 `BanditArm::new(key, ...)`）且池内 `addr` 唯一 ⇒ 两者等价。
  平局语义不变（`score > best_score` 严格大于 ⇒ 首个最大值胜出）。

**⚠️ 关键陷阱（必须避开，否则死锁）:** `arm_for` 冷路径会 `arms.insert(...)`。
若流式实现**同时持有 `bandit_arms` 的 `ref()` guard** 再调 `arm_for`，
同分片会死锁。正确做法：只在 `arm_for` 内部做**短生命周期** `get()`
（`arm_for` 现已如此），外部**不跨 `arm_for` 调用持有** `bandit_arms` 的 ref。

**收益边界（诚实标注）:** 这是**分配/缓存局部性**优化，不改变 asymptot 的
O(N) 遍历（bandit 打分本身就是 O(N·d²)，语义要求看到全部臂）。`ArcSwap::load()`
的 guard 是引用计数而非阻塞锁，故两趟遍历不阻塞写侧。

**兼容性:** `get_healthy_candidates_excluding` 是 `pub`，仍被 prober
（`main.rs:619/629`）与 prewarmer（`pool.rs:88/94`）及单测使用 ⇒ **保留该 API**，
只让数据面热路径不再走它。

**验证:** ①语义等价——固定 seed 下新旧实现选中同一节点（穷举小池）；
②零分配契约——沿用 OPT-R9/R10 已建成的 crate 级 `test_allocs` 串行门。

## C 组（P1，资源/安全）

### C1 `quarantine_map` 外层 key 无界

**已核实** `router.rs:97` 类型 + `router.rs:157-160` 写入点：

```rust
quarantine_map: DashMap<String, DashMap<String, Instant>>,   // 外层 key = normalize_domain(domain)
self.quarantine_map.entry(normalize_domain(domain)).or_insert_with(DashMap::new).insert(ip.to_string(), expiry);
```

外层 key 是**客户端可控的归一化 `Host`**。攻击者用随机 Host 反复吃 403/429
即可在 TTL 窗口（403→600s）内膨胀该表。`sweep_expired_at`（`router.rs:204-207`）
会回收空内层 map ⇒ 是**时间有界（TTL）而非绝对有界**，但 600s × 无上限条目数
在高 QPS 下是真实的内存放大面。

`apply_delta`（`main.rs:566`）的 Redis PubSub 入口更直接：`parse_delta_message`
（`circuit_breaker.rs:46-63`）只校验 `ttl` 范围与 domain/ip 非空，**不校验
domain 长度** ⇒ Redis 可达者可注入任意 domain 灌入。

**已有先例:** 会话表已做双层防护（`router.rs:22/27/112-119`
`SESSION_ID_MAX_BYTES=64` + `SESSION_MAX_ENTRIES=8192`）。隔离表**两样都没有**。

**修法:** 对齐会话表做法——①`QUARANTINE_MAX_DOMAINS` 外层条目水位；
②domain 长度上限 `QUARANTINE_DOMAIN_MAX_BYTES`。**行为影响须显式声明**：
超限的 domain 不落表（与超长 session_id 不落表的既有语义一致），
`quarantine_len()` 因只统计内层条目数，水位拒绝不改变它的返回值口径。

## 5. 明确**不做**的事（避免制造不存在的威胁或未授权的行为变更）

| 项 | 为何不做 |
| -- | -------- |
| "API Key 改常量时间比较" | **不存在时序攻击**：`tenant.rs:119` 用 `DashMap::get` 哈希查找，比裸 `==` 安全。加 `subtle` 依赖是为一个不存在的威胁模型增加供应链面。 |
| `default_key` 策略收紧（审计 Top5 #5） | **属行为变更**：改默认 key / 缺省即启动失败会让现有部署升级即挂。**需用户决策**，不擅自改。已记入本方案待办。 |
| Linux `host.docker.internal` / PSScriptAnalyzer | 本机无 Linux / NuGet provider 缺失装不上，已在 R9/R10 诚实登记。 |
| CH Prometheus exporter | 需引入新依赖，超出本轮范围。 |
| `circuit_breaker.rs:117` 扁平 key 用 `:` 拼接 | 跨实例 PubSub/Redis 协议 key，**改它会破坏与其它实例的互操作**。仅记录，不动。 |
