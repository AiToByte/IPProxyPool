# 生产正确性与标准代理优化实施计划

日期：2026-11-09。来源：本会话全项目分析与用户明确实施授权。

## 产品目标与范围

将当前智能出口网关逐步完善为可验证、可运维的多供应商出口调度平台。优先修复可复现的数据丢失、凭据暴露及控制策略冲突，再交付标准协议与生产化。所有新增关键注释采用中文；沿用 Rust/Pingora/Axum 架构，不引入未经证明必要的基础设施。

## 架构与约束

- 配置意图、运行健康、自动策略不能用同一个状态隐式覆盖。
- 租户写回保持请求路径无网络等待，写回确认必须关联具体修改版本。
- Redis Stream 消费者有 pending 时不可删除；当前去重只能承诺进程内窗口，不宣称跨重启恰好一次。
- 日志不得记录具有认证能力的路径参数。
- 开关只有全链路接通才允许启用；未实现的分片必须启动拒绝。
- CONNECT、TLS 入站、上游 TLS 分别验收；不通过关闭证书校验解决身份问题。
- 不改写历史执行记录；不覆盖用户已有 repomix-output.xml 改动；本轮未获提交/推送请求，不创建提交。

## P0 技术设计

1. Admin 日志清洗所有租户资源路径中的凭据，包括未知后缀和编码路径；保持 API 兼容。
2. 将 TenantManager 脏集合升级为 key→版本。写快照前捕获版本，成功后条件删除同版本；异步 mutex 串行 flush，不跨 await 保留 DashMap 守卫。写失败和取消均不清脏。
3. sink 只删除 pending 为零的闲置消费者；pending 保留给 XAUTOCLAIM。对跨进程幂等边界如实注释。
4. 回放查询对齐权威 DDL 的 proxy.proxy_telemetry_log/event_time；本地 HTTP stub 覆盖真正请求与 JSONEachRow 解析，保留毫秒精度。
5. 在依赖连接之前验证 REDIS_STREAM_SHARDS，只接受当前消费者支持的单 stream；错误配置不可借依赖离线绕过。
6. 自动倍率不复活零权重节点，配置调权同步更新基准，避免旧基准恢复错误。

## 验证策略

每项先添加测试并实际复现 RED，再修复为 GREEN。并发测试使用 Notify/可控后端制造精确窗口，避免 sleep 猜时序。执行 Rust fmt/clippy/test、Python unittest 与现有结构门；环境具备时运行真实 Redis/CH 集成。覆盖率优先关注新增逻辑，现有总体基线低于 80% 需明确记录，不宣称达标。汇总后进行独立 Rust/安全/通用代码审查。

## 风险

- 当前 Docker daemon 不运行：真实后端恢复实验需要可用依赖；模拟测试不能冒充真实后端测试。
- 部分静态门验证结构而非行为；修复后必须有行为测试佐证。
- 节点禁用保护的最小修复不能替代后续配置/健康状态分离。
- 单实例周期写回不是账务账本，也不解决多实例余额并发覆盖。
