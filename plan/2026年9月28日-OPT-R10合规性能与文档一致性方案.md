## 关键设计决策（先定口径，再动手）

### 决策 1：MaxMind 署名——为何这是本轮最高优先级

**实证（已核对）**：

- `docs/OPEN-SOURCE.md:37`（中文）写：「**MaxMind GeoLite2**（可选数据库文件，不在仓库内）**需在使用时署名**（OPERATION 有署名行）；更新器需要你自己的 license key。」
- `docs/OPEN-SOURCE.md:78`（英文）写：「attribution required when used (**attribution line in OPERATION**)」
- 实际 `docs/OPERATION.md:94-97` 只有 GeoLite2 的**操作说明**（库路径、cron 命令、license key 环境变量），**没有任何署名行**。

⇒ 文档**两次声称已履行，实际未履行**。GeoLite2 数据库是 **CC BY-SA 4.0**，
该许可**强制要求**署名（Attribution 4.0 International §3(a)）。这与其它
技术债不同——它是**法律风险**，且随「是否在生产启用 GeoIP」而实际发生。

**修法：** 在 `OPERATION.md` 的 GeoLite2 章节加**显式署名块**，包含
MaxMind 官方要求的四要素：产品名、数据集名、许可名+链接、数据来源 URL。
同时**修正 `OPEN-SOURCE.md` 的措辞**——它现在说「OPERATION 有署名行」，
本轮补上后该说法才成立（此前是**不实陈述**，需一并纠正）。

**为何不把署名放 README：** 署名要求「随数据集分发时附带」。README 是仓库门面，
但 GeoLite2 数据库**不在仓库内**（`OPEN-SOURCE.md:78` 明确 "not in repo"），
署名义务实际发生在**部署方**使用该数据库时。`OPERATION.md` 是部署操作手册，
是署名的正确落点；同时在 README 加一行指向，避免读者只看门面时无从得知。

### 决策 2：`arm_for` 热点——为何「先查后建」不能省，以及真正的解法

**现状（`gateway.rs:61-69`，已实证）**：

```rust
pub fn arm_for(arms: &DashMap<String, Arc<BanditArm>>, node: &ProxyNode) -> Arc<BanditArm> {
    let key = node.addr.clone();          // ← 每次调用都克隆
    if let Some(existing) = arms.get(&key) {
        return existing.value().clone();   // 命中时：白克隆了
    }
    ...
}
```

调用点在 `select_bandit_node_excluding`（`:253`）的
`candidates.iter().map(|n| arm_for(&self.bandit_arms, n)).collect()`
⇒ **池 N 时每请求 N 次 `String` 克隆**（免费池缺省 2000 节点 ⇒ 约 2000 次/请求）。

**能省掉那次 clone 吗？** `DashMap::get` 接受 `&str` 做借用查询（`Borrow`），
所以命中路径其实**不需要**拥有 `String`：

```rust
if let Some(existing) = arms.get(node.addr.as_str()) { return existing.clone(); }
// 只有真正新建臂时才分配 key（此处 node.addr.clone() 是必需的）
```

⇒ 命中路径从「克隆 + 哈希 + 克隆 Arc」降为「哈希 + 克隆 Arc」，**零字符串分配**。
这与 OPT-R9 C1 同源（把分配从热路径挪到冷路径），但**改动面小得多**。

**为何不需要动臂表键或生命周期**（审阅原建议是「需改键生命周期」，实测后不成立）：
臂表键就是 `node.addr`，`prune_stale_arms` 也以它比对存活节点。本方案**完全不动
键语义**，只改查询方式 ⇒ 零回归风险。

**进一步优化（是否做）：** 还能把「每请求遍历全部候选建臂向量」也省掉吗？
不能——LinUCB 需要每个候选的臂分数，那是算法本身。**故本轮只做零分配化，
不动算法**（算法改动属 `docs/SPIKE_R2.md` 记录的 OUT 范围）。

### 决策 3：SDK 错误契约——统一到「异常用于编程错误，返回值用于网络失败」

**现状（逐个 grep 实测）**：

| SDK | 非 http 目标（编程错误） | 网络失败 |
|---|---|---|
| Python | `raise ValueError` | 返回 `(0, body)` |
| Node | `throw new Error` | 返回 `{status:0}` |
| **Go** | **`return 0, []byte("only plain http...")`**（不抛！） | 返回 `(0, err)` |
| Java | `throw new IllegalArgumentException` | 返回 `out[0]=0` |
| **.NET** | **`:81` throw / `:79` catch 里 return —— 同方法混用** | 返回 `(0, msg)` |

**不一致的危害（真实）**：
- Go 用户照 Python 写法只判 `status != 200`，非 http 目标会**静默**走到
  `status == 0` 分支而拿不到任何错误信息；
- .NET 同一方法内两种通道，调用方无法用统一方式捕获。

**统一口径（跨语言的最小公倍数）：**

1. **编程错误**（非 http 目标、非法参数）→ **抛异常**（Go 用 `error` 返回值，
   因 Go 的惯例是 error 而非 panic——这是**语言惯例差异，不是契约不一致**，
   需在文档中显式说明）；
2. **网络/网关失败**（连接失败、超时、503 重试耗尽）→ **返回零状态码 + 诊断信息**，
   **不抛**——因为这些是**运行期可预期**的瞬时故障，抛异常会迫使调用方写
   try/catch 吞掉它们，反而丢失可观测性。

⇒ Go 的「非 http 返回 0」与 .NET 的「同方法混用」是**偏离**，要改；
其余三个已符合口径，只需在**文档中把口径写清楚**（当前 `USAGE.md:57-59` 只说
「语义同 Python SDK，详见各文件头注释」，把责任推给了 5 份各自的头注释）。

**加校验门：** 新增 `tools/check_sdk_contract.py`，断言 5 个 SDK 的
「非 http 目标」分支都走**抛异常/返回 error**（而非静默返回 0），
防止将来新增 SDK 时偏离。**如实标注**：文本断言只能覆盖「写法形态」，
**不能证明运行时行为正确**（那需要各语言的真实单测，属后续立项）。

### 决策 4：文档口径——为何「单测数」不该手写

**现状（grep 实测）**：同一件事有 **4 个不同数字**散落——
`COMPONENTS.md:5`=156、`README.md:14/49`=201、`FEATURES.md:4`/`TASK_PLAN.md`=209、
实际（OPT-R9 后）=**235**。

**根因：** 数字是**手写**的，每轮迭代都要人肉更新，漏一处就漂移（本仓已漂 4 次）。

**修法（两段）：**
1. **本轮把全部过期数字更新为真值**（235），并标注「截至 OPT-R10」；
2. **加校验门** `tools/check_doc_consistency.py`：断言
   `docs/`、`README.md`、`CHANGELOG.md` 里出现的「N unit tests / N 单测」
   **全部一致**（正则抽取数字比对）。这样下次迭代漏改会**在 CI 红**。

**为何不做「自动生成」**（把数字注入文档）：需要模板引擎或构建期替换，
引入新工具链复杂度；校验门用 30 行 Python 就能达到「漏改即红」的效果，
**收益/成本比高得多**。

**孤儿文档处置：**
- `docs/USAGE.md`（10.5 KB，**0 入链**）：内容与 `USER-GUIDE.md`/`USER-MANUAL.md`
  三重重叠，但它是**唯一**给出「SDK + 适配器 + PAC + 系统代理」完整操作路径的文档。
  **修法**：不删（内容有价值），改为在 `README` 文档索引中**补上入口**，
  并在文件头标注「与 USER-GUIDE 的关系」（谁查什么），消除「重叠但无人知」。
- `manual/`（122 KB，**0 入链**，**纯中文无双语**）：原始设计备忘录，
  内容**与现网冲突**（写 `0.0.0.0:8080`，现为 `127.0.0.1:8916`；要求
  「P99 < 5ms」而实测 65ms）。**修法**：**不删历史**（有审计价值），
  加 `manual/README.md` 说明「历史设计记录，已被 `docs/` 取代，勿据此操作」，
  并在 `manual/` 每个文件**顶部插入 deprecation 横幅**。
- `banyan-skills` 悬空引用：`OPERATION.md:3` 与 `EXEC_LOG.md:3` 引用它，
  但它被 `.gitignore` 排除（非 submodule、无 pin）⇒ **新 clone 必然悬空**。
  **修法**：把这 2 处改为**纯文字说明**（"方法论底座，独立仓库，不随本仓分发"），
  消除悬空链接语义；不引入 submodule（那会改变仓库分发形态，属更大决策）。
