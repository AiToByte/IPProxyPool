## 拆解

### OPT-1 三 Map sweep（router.rs + gateway.rs）
- `RouterEngine::sweep_expired(now)`：删 `session_store` 中过期（>600s）条目、删 `quarantine_map` 中过期条目；返回删除数。
- `SmartProxyGateway::prune_arms()`：以当前池 `addr()` 集合为白名单，删 `bandit_arms` 中游离臂；返回删除数。
- 复用 `pool.rs` 30s ticker 节拍：在 `ConnectionPrewarmer::run` 同循环或 main 另起 60s ticker调用两者并打 info 日志（删了多少）。
- 顺手清过期 allow：`model.rs:41` 整行注释更新（GW-4 已落地）、`router.rs` 4 处"Consumed by"注释（已消费，allow 留但注释改"稳定 API"或直接去 allow——验证 clippy 不报再去）。
- 单测：router 塞过期/有效混合条目 → sweep 后只剩有效；gateway 级用小池验证 prune（需构造 SmartProxyGateway ——字段全 pub，可直构）。

### OPT-2 API Key 环境门（gateway.rs + main.rs）
- `main.rs` 读 `REQUIRE_API_KEY`（`std::env::var == "1"` 即开，默认关，compose 注释示例）。
- `SmartProxyGateway` 加 `require_api_key: bool` 字段；`request_filter`：开且无 `X-API-Key` 头 → 403 拦截（不走 tenant 查询，`tenant_account=None`，logging 不释放——语义与坏 Key 一致）。
- curl 验证两档；OPERATION §2 加一行说明。

### OPT-3 重试计量口径（gateway.rs）
- 语义冻结：只计最后一次 attempt 的出站字节（失败 attempt 的字节不进账单）。
- 实现：`fail_to_connect` 首行 `ctx.transferred_bytes = 0`（新 attempt 从零累计）+ 注释；`logging` 不动。
- OPERATION §4 计费行补口径声明。单测：port 口径是网关行为，单测覆盖 `compute_reward` 不变——以 curl + 代码走查验收（e2e 里强制一次失败重试难造，记为已知限制）。

### OPT-4 落库重试 + 丢弃计数（telemetry.rs + metrics.rs + main.rs）
- `TelemetryWorker` 加 `dropped: Arc<AtomicU64>` 字段（`new`  sights 参数——改签名，main 唯一调用点同步改）。
- `flush` 失败 → 睡 100ms 重发一次 → 仍失败则丢弃并 `dropped += batch_len`（原来静默丢）。
- `metrics.rs` 加 `telemetry_dropped_total` 计数器 + render；`logging` 不动（worker 侧直接写 counter，无需经 gateway）。
- main 把同一个 `Arc<AtomicU64>` 同时给 worker 和 metrics（metrics 加 `set_dropped_watcher` 或构造参数——选构造参数，改一处）。
- 单测：render 含 dropped 行；flush 重试逻辑以 live（Redis 停启）为验收，日常以 clippy+走查为准。

### OPT-5 Prober 共享 Client（prober.rs）
- `CanaryProber { client: Client }`，`new()` 内一次 `Client::builder().timeout(2500ms).build()`（失败则 fallback 空——builder 失败率极低，`expect` 并注释，或存 `Option`；选 `Option` 降级为 Dead，不 panic）。
- `probe_node` 用共享 client + `reqwest::Proxy::all(proxy_url)` per-call（Proxy 是 per-request 可配，Client 复用成立）。
- 现有 2 单测不动（纯函数区）；验收：clippy + 60s 日志无异常 + curl 回归。

### OPT-6 真预热（pool.rs）
- `warm_once` 改为：对每个候选节点 `tokio::net::TcpStream::connect(addr)` 1s 超时，spawn 并发，统计 `connected/failed`，返回 `(tickets, connected)` 或保持返回 warmed 数并加日志字段。
- 日志如实：`[Prewarmer] tick nodes=3 connected=3 failed=0`；失败只 debug（Mock 是 plain-HTTP，能连上；连不上也不影响主链路）。
- 单测：对 `127.0.0.1:1`（必拒） warm → failed 路径不 panic；对本地临时 listener → connected 计数。用 `tokio::net::TcpListener::bind("127.0.0.1:0")` 起临时端口，零外部依赖。
- 保留 Chrome profile 构造（peer option 回归仍被 `fingerprint` 单测覆盖）。
