# 主动健康探测闭环实施计划（步骤 54）

> 日期：2026-10-26
> 上游依据：`docs/CAPABILITY-AUDIT.md` §4「被动隔离」与 §8 路线建议第 3 条
> ——「主动健康探测 — 补齐隔离闭环（当前纯被动）」。

## 0. 路线决策：为什么先做第 3 条，而不是第 2 条

审计 §8 第 2 条写的是「HTTPS 入站 + PAC 分发 — 解锁真实企业接入场景
（浏览器/移动端）」。本轮取证发现它不是一个可单步收口的改动：

| 事实 | 证据 |
| --- | --- |
| Pingora 0.9 只提供 CONNECT 的**放行开关**，不提供隧道数据面 | `pingora-proxy-0.9.0/src/lib.rs` 的 `allow_connect_method_proxying` 分支仅做 method 检查；`proxy_h1.rs` 无 CONNECT 隧道逻辑 |
| 本仓网关没有 CONNECT 处理 | `gateway/src/gateway.rs` 无 `Method::CONNECT` 分支；`tools/ipp_forward.py` 对 CONNECT 显式 501 |
| 浏览器访问 HTTPS 必须经过 CONNECT | PAC 只能返回 `PROXY/HTTPS host:port`，无法把 `CONNECT` 变成普通 HTTP 请求 |

因此「HTTPS 入站 + PAC」实际包含三个能力：CONNECT 隧道、TLS 入站、
PAC 生成/分发。把它硬塞进一个步骤会得到「TLS 能握手、浏览器仍不能上网」的
半成品，且容易在文档里写成已完成。**本步不做第 2 条**；第 2 条另立专项计划，
按「CONNECT → TLS 入站 → PAC」拆分，逐项验收。

本步选择第 3 条，因为：

1. 现有 `CanaryProber` 已经在每 60s 探测节点，但结果只写日志，**选路完全
   不消费**——这是“有探针、无闭环”的真实缺口；
2. 它不依赖 CONNECT/TLS/PAC，可独立交付、独立回滚；
3. 它直接改善坏节点暴露时间：空闲节点不再需要等真实流量才被隔离。

## 1. 目标

让主动探测结果**真正影响选路**：连续探测失败的节点在冷却期内不再被选中，
恢复后自动回到候选池；同时保证不会因为探针自身故障把所有节点一次性摘光。

验收口径（可执行）：

1. 60s prober 探测**全部 `weight > 0` 节点**，包括当前已被主动健康判定为
   不健康的节点（否则坏节点永远没有恢复机会）。
2. 连续 `PROBE_FAILURE_THRESHOLD` 次 `Dead` 后，节点在
   `PROBE_UNHEALTHY_COOLDOWN_SECS` 内不参与新鲜选路，也不得被粘滞会话
   继续命中；下一次 `Healthy`（或 `Degraded`，见 §4.4）立即恢复。
3. **安全阀**：任何时刻至少保留 1 个 `weight > 0` 的节点不被主动健康摘除；
   即使所有探测都失败，网关也不因主动健康本身返回全池 503。
4. 冷却到期后节点重新可被真实流量尝试；若仍失败，下一轮探测可立即重新标记
   （不要求再等一个完整阈值周期）。
5. 节点被删除/免费池整组替换时，对应健康状态同步清理，`DashMap` 不随运行
   时长无界增长。
6. 新增两个稳定指标：
   - `active_probe_results_total{result="healthy|degraded|dead"}`（counter）
   - `active_probe_unhealthy_nodes`（gauge，当前被主动健康摘除的节点数）
7. 真实二进制 E2E：两个本地 mock 节点，杀掉一个后指标从 0→1、流量只命中
   存活节点；重启后指标 1→0、流量重新命中恢复节点。
8. `cargo fmt/clippy/test`、离线 Python 门、文档一致性门全绿；单测基线按
   实测值更新，不预填。

## 2. 非目标（明确不做，避免范围蔓延）

- CONNECT 隧道、TLS 入站、PAC 生成/分发（另立专项，见 §0）。
- 在 Admin API/UI 暴露逐节点健康状态（本步用日志＋指标；逐节点字段需要
  OpenAPI/UI/门禁一起改，另立小步）。
- 主动健康状态持久化（进程重启后清空，由下一轮探测重建；避免把瞬时健康
  状态写进 `nodes.json`）。
- 新增告警规则（先提供指标；阈值需结合真实池规模调，避免“单节点不健康”
  就告警的噪声）。
- 可配置探测目标 URL（继续用现有 Cloudflare trace 双源；目标可配置会扩大
  SSRF 面，另议）。
- 改变 `Degraded` 的既有语义（可达但状态异常仍只告警，不作为健康摘除依据）。
- 按 tier/country/proto 做多维度 quorum（本步只做全局“至少留 1 个”安全阀）。

## 4. 设计

### 4.1 RouterEngine 内的主动健康状态

新增字段（`gateway/src/router.rs`）：

```text
active_health: DashMap<String /*addr*/, ActiveHealthState>
active_unhealthy_count: AtomicUsize
eligible_nodes: AtomicUsize
probe_failure_threshold: u32
probe_unhealthy_cooldown: Duration
```

`ActiveHealthState`：

```text
consecutive_failures: u32
unhealthy_until: Option<Instant>
```

语义：

- `unhealthy_until = Some(t)` 表示“主动健康摘除到 t”；
- `consecutive_failures` 在成功时清零（直接删条目），在失败时饱和递增；
- `active_unhealthy_count` 维护 `unhealthy_until.is_some()` 的条目数，供
  O(1) 热路径快速判断和安全阀使用；
- `eligible_nodes` 在 `store_nodes` 时按 `weight > 0` 重算；
- 阈值/冷却在构造时注入，默认 `3` 次 / `300s`，并由 env 覆盖（§4.5）。

### 4.2 选路过滤

- `matches` 在 weight/proto/country/tier 之后、域级 quarantine 之前增加：
  `if self.is_active_unhealthy(&node.addr, now) { return false; }`
- 粘滞快路径的 `still_live` 条件增加同一判定：绑定节点一旦被主动健康摘除，
  下一次请求自动迁移到其他候选。
- `get_healthy_candidates*`、分桶快路径、全量回退都复用 `matches`，无需各自
  复制逻辑。
- 新增 `probe_candidates()`：返回全池 `weight > 0` 节点（**绕过** `matches`），
  专供 prober 使用。这样被摘除的节点仍会被探测，恢复后能回到池中。

### 4.3 结果回灌

新增方法：

```text
record_probe_success(addr) -> bool           // true = 从“摘除”恢复
record_probe_failure(addr) -> ProbeFailureOutcome
sweep_active_health()
active_unhealthy_len() -> usize
probe_failure_threshold() -> u32
probe_unhealthy_cooldown_secs() -> u64
```

`ProbeFailureOutcome` 至少包含：

- `BelowThreshold`：失败已计数，但未达到阈值；
- `MarkedUnhealthy`：本次首次进入摘除；
- `RefreshedUnhealthy`：已在摘除中，刷新冷却；
- `SuppressedLastNode`：安全阀阻止本次摘除；
- `NodeGone`：探测期间节点已被删除/权重归零，不落状态。

成功路径删除条目并递减计数；失败路径按阈值置 `unhealthy_until`。冷却到期由
`sweep_active_health()` 将 `unhealthy_until` 清为 `None`，保留
`consecutive_failures`，使“仍失败”的节点在下一次失败时立即重新摘除。

### 4.4 prober 主循环

- 每 tick 先 `sweep_active_health()`，再取 `probe_candidates()`。
- 信号量关闭导致的“跳过探测”改为返回 `(node, None)`，**不更新健康状态、
  不记探测结果指标**；避免把关机/过载误判成节点死亡。
- `Healthy`：`record_probe_success`；指标 `healthy`。
- `Degraded`：可达但状态异常，**按成功处理**（清除连续失败），指标
  `degraded`，保留 warn 日志。理由：Cloudflare/备源对代理出口返回 403/5xx
  不代表节点传输层已死；把它当失败会制造大面积误摘。
- `Dead`：`record_probe_failure`；指标 `dead`；按 outcome 打不同日志
  （首次摘除/刷新/安全阀阻止/未达阈值/节点已删除）。
- tick 结束刷新 `active_probe_unhealthy_nodes` gauge。
- 保留 `PROBE_ACTIVE_HEALTH_ENABLED` 总开关（默认开）：关闭后仍探测/记指标，
  但不改选路，供探针目标异常时快速止血。

### 4.5 安全阀与配置

**安全阀**：`record_probe_failure` 在“首次摘除”前检查：

```text
active_unhealthy_count + 1 >= eligible_nodes  ⇒ SuppressedLastNode
```

即：若摘除后没有任何 `weight > 0` 节点可用，则保留该节点。它可能仍是坏的，
但比主动健康自己制造全池 503 更安全；真实流量失败仍由既有被动隔离处理。
节点已经处于摘除状态时刷新冷却不受此限。

配置（`main.rs` 读取，启动日志打印生效值）：

| 变量 | 默认 | 约束 | 含义 |
| --- | --- | --- | --- |
| `PROBE_INTERVAL_SECS` | 60 | >0 | 既有探测间隔 |
| `PROBE_FAILURE_THRESHOLD` | 3 | clamp 1..=10 | 连续 Dead 多少次后摘除 |
| `PROBE_UNHEALTHY_COOLDOWN_SECS` | 300 | clamp 1..=86400 | 摘除冷却 |
| `PROBE_ACTIVE_HEALTH_ENABLED` | true | 0/false/off 关闭 | 总开关 |

### 4.6 指标

在 `MetricsRegistry` 增加：

```text
# HELP active_probe_results_total Active health probe results by outcome.
# TYPE active_probe_results_total counter
active_probe_results_total{result="healthy"} N
active_probe_results_total{result="degraded"} N
active_probe_results_total{result="dead"} N

# HELP active_probe_unhealthy_nodes Nodes currently removed by active health.
# TYPE active_probe_unhealthy_nodes gauge
active_probe_unhealthy_nodes N
```

三行 counter 固定渲染（即使为 0），避免 Dashboard/告警在首次探测前无序列。
`note_active_probe_result` 只接受三个固定标签值，拒绝任意标签，防基数爆炸。

### 5.2 真实二进制 E2E

准备两个本地 mock 节点（一个 Python 进程内两个端口即可）：

- 对 `CONNECT host:port`：建立到目标的 TCP 隧道并回 200，用于让 prober
  的 `https://cloudflare.com/cdn-cgi/trace` 真正走通；
- 对其他请求：返回带节点标识的 200 响应体（A/B）。

步骤：

1. `NODES_FILE` 指向临时文件（只含 A、B 两节点），启动网关：
   `PROBE_INTERVAL_SECS=1`、`PROBE_FAILURE_THRESHOLD=2`、
   `PROBE_UNHEALTHY_COOLDOWN_SECS=30`。
2. 等 `active_probe_results_total{result="healthy"} > 0`，确认
   `active_probe_unhealthy_nodes 0`。
3. 发若干请求，确认 A/B 都能被命中。
4. 杀掉 B；等 gauge=1、`dead` 计数 >=2。
5. 再发请求，响应体只能出现 A（B 已被摘除）。
6. 重启 B；等 gauge=0，确认 A/B 重新都能命中，日志出现恢复行。
7. 收尾：停网关/mock，删除临时 `NODES_FILE`，确认无残留进程与端口。

若本机外网不可达，E2E 必须如实标注“未执行”，不得用单测冒充；本次执行前
已用 `curl https://cloudflare.com/cdn-cgi/trace` 取证外网 200，预期可跑。

## 6. 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 探针目标被墙/抖动导致大面积误摘 | 仅 `Dead` 计入；`Degraded` 不清除也不摘除；阈值默认 3；冷却 300s；`PROBE_ACTIVE_HEALTH_ENABLED=0` 总开关 |
| 全池被摘光 | 安全阀保证至少 1 个 `weight>0` 节点；单测锁定 |
| 健康状态无界增长 | `store_nodes` 按当前池 addr 剪枝；`sweep_active_health` 清过期；池替换测试 |
| 重启后状态丢失 | 设计为非持久化；重启后由首轮探测重建，不影响正确性（只影响恢复速度） |
| 热路径变慢 | 用 `active_unhealthy_count == 0` 快速短路；正常态零额外哈希查找 |
| 回滚 | 设 `PROBE_ACTIVE_HEALTH_ENABLED=0` 立即停止摘除；代码回滚只涉及 Router/prober/metrics 三处 |
