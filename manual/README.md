# manual/ — 归档说明（v1 设计草稿，非部署文档）

> **本目录是历史归档，不是当前文档。** 每份文件顶部都带有「已废弃」横幅。

## 为什么保留这些文件

这些是 v1 阶段的设计草稿（架构备忘录与 A1~A4 细化执行记录）。它们**已被
后续 30+ 轮迭代超越**，但保留下来有两个价值：

1. **设计演进可追溯** —— 能看出「先想到什么、后来为什么改」，比只留最终态
   更有信息量。
2. **回归时的对照物** —— 当有人问「当初为什么用 X」时，这里可能有答案。

## 为什么不删

删除会丢失演进轨迹，而这些文件**没有任何运行时作用**（不被构建、不被测试、
不被任何入口链接）。留着的唯一成本是 122KB 磁盘。

## 已知失实内容（**不要照抄**）

| 失实项 | 实际情况 |
| ------ | -------- |
| 端口 `0.0.0.0:8080` | `:8916`（OPT-R5 起，避让 traefik 争用） |
| P99 < 5ms | dev 基线约 **65ms**（Windows debug 参考值，非生产承诺） |
| 组件/鉴权清单 | 早于 CH 迁移、supervisor、free_pool 等多轮架构迭代 |

**保留历史错误原文**是刻意的：改掉它就等于伪造了当时的记录。这些文件是
**史料**，史料不该被修饰——但必须有醒目的横幅，防止有人把它当部署依据。
