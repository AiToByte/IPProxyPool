- 评估日期：2026-11-26。
- 源码基准：`c5d62c1`，分支 `feat/world-class-production-hardening`，包版本 `0.2.0`。
- 依据：当前源码与配置、仓内质量基线、历史实测记录，以及本次分析会话执行的本地检查。
- 性质：工程状态评估，不构成生产 SLA、安全认证或独立商业评测。
- 本文是有日期的快照；后续测试数字以 [QUALITY_BASELINE.md](QUALITY_BASELINE.md) 为准，运行状态以最新 [EXEC_LOG.md](../EXEC_LOG.md) 和源码为准。

## 1. 阅读结论

**项目已经具备基础代理业务闭环，可以用于程序接入、实验和受控试用；目前仍在生产可信化加固，不能把基础功能可用等同于成熟企业生产平台。**

| 你关心的问题 | 当前结论 |
| --- | --- |
| 能否自动获取免费代理地址？ | 能，已有抓取、验证、入池和健康治理实现；需要显式启用。 |
| 能否通过免费代理访问网址并把响应返回客户端？ | 能，普通 HTTP 路径已有历史公网成功实测记录。 |
| 是否只是收集 IP，没有真正转发？ | 不是。历史实验中客户端收到了目标网站返回的代理出口 IP，并有服务端记录交叉核对。 |
| 今天启动是否一定有可用免费节点？ | 不能保证。供给会波动，池可能为空，检测通过的节点也可能迅速失效。 |
| 能否给所有浏览器和应用直接设置系统代理使用？ | 不能这样承诺。程序入口、HTTP 适配器、独立 CONNECT 入口的能力不同。 |
| 是否已达到企业级 HA、商业 SLA 和多实例计费一致性？ | 尚未证明，相关能力或验收仍有缺口。 |

必须区分“源码已实现”“特定环境验证通过”“当前部署稳定可用”。本次分析确认了前两类证据，**没有重新启动当前版本执行公网免费代理闭环，因此不宣称当前环境此刻已跑通。**

## 2. 项目目前到了哪个阶段

### 2.1 产品定位

IPProxyPool 更准确的定位是“多供应商智能出口代理网关”：管理出口节点，按条件选路，参与健康治理，处理租户限额并记录遥测。

它已超出简单 IP 列表采集脚本的范围，具备多个可协作运行的工程模块；但它没有自带大规模、稳定且有商业 SLA 的住宅、ISP 或移动代理网络。

### 2.2 开发阶段

根据 [顶级项目演进落地计划](../plan/2026年11月18日-顶级项目演进落地计划.md)，当前为 **E0 已完成、E1 进行中**。

## 3. 免费代理闭环如何工作

### 3.1 完整流向

```text
准备阶段：
公开代理源 → 获取候选 IP:端口 → 连通性/出口/匿名度等验证 → 节点入池

请求方向：
客户端应用 → IPProxyPool 网关 → 免费代理服务器 → 目标网站

响应方向：
客户端应用 ← IPProxyPool 网关 ← 免费代理服务器 ← 目标网站响应

反馈方向：
请求结果 → 计量/遥测/健康反馈 → 后续选路和节点治理
```

实际转发流量的是 `IP:端口` 对应的代理服务。代理入口 IP 与最终出口 IP 可能不同；目标网站通常看到的是出口 IP。透明代理还可能通过请求头暴露客户端信息，所以“经代理访问”和“匿名性有保证”不是同一结论。

本项目处理接入的应用层代理请求或受支持隧道，**不是自动接管整台机器所有网络流量的 VPN**。应用需要按对应入口接入。

### 3.2 各环节能力与限制

| 环节 | 当前能力 | 现实限制 |
| --- | --- | --- |
| 获取代理 | 多源抓取与解析 | 来源可能不可达、数据过期、零产出。 |
| 验证代理 | 分级探测、出口、匿名度及可选 GeoIP 判断 | 检查是时间点结果，不保证长期存活或对所有目标可用。 |
| 维护代理池 | 路由池合并、健康反馈、隔离恢复 | 节点数量会变化，可能归零。 |
| 接收应用请求 | 程序、SDK、HTTP 适配器、可选 CONNECT | 不同入口的格式和协议范围不同。 |
| 选择并转发 | 免费档、协议、地区等条件筛选 | 条件过严可能没有匹配节点。 |
| 返回网站响应 | HTTP/SOCKS 出站与响应返回已实现 | 代理失效、网络限制、目标拒绝仍会造成失败。 |
| 核验出口归属 | 指标、遥测及可选数仓交叉核对 | 只有指标增长或一个 200，不能单独证明出口正确。 |

### 3.3 已有真实公网实测

`EXEC_LOG.md` 的 2026-09-30 步骤 41 记录了访问公网 IP 回显网站的实验：

| 项目 | 历史结果 |
| --- | --- |
| 总请求 | 3,400 次 |
| 实际尝试免费代理 | 85 次 |
| 免费代理成功且返回真实出口 IP | 39 次 |
| 免费尝试失败 | 46 次 |
| 免费尝试成功率 | 39/85 = 45.9% |
| 出口身份 | 12 个 |
| 客户端成功数与 ClickHouse 统计 | 39 与 39 一致 |
| 当时本机公网 IP 出现在代理响应中的次数 | 0 次 |

其他请求大部分进入了实验配置的本地付费 mock，所以不能用 3,400 作为免费尝试成功率的分母，也不能说整批请求全部通过真实免费代理。

该记录证明当时普通 HTTP 闭环成立。它不证明今天仍有 45.9% 成功率、旧节点仍可用、任意网站均可访问，或者当前 HTTPS/CONNECT 已完成同等实网验收。

## 4. 怎样进行实际接入

### 4.1 先验证普通 HTTP 程序请求

当前常规入口主要采用“请求发给网关，真实目标放在 `Host` 头”的契约。见 [USAGE.md](USAGE.md)。

下面是调用示例，前提为：

- 网关已启动，处于允许接收请求的状态。
- 网关启动时配置了 `FREE_ENABLED=1`，并已产生可用免费节点。
- 客户端 `$env:IPP_API_KEY` 为网关中已登记、启用且额度有效的租户 Key。设置客户端变量不会自动创建租户。
- 免费池有适用于本次请求的 HTTP 节点。

```powershell
curl.exe --noproxy "*" --max-time 40 `
  "http://127.0.0.1:8916/ip" `
  -H "Host: httpbin.org" `
  -H "X-Api-Key: $env:IPP_API_KEY" `
  -H "X-Proxy-Tier: free"
```

这表示通过免费出口请求 `http://httpbin.org/ip`，将响应返回 curl。目标服务自身也可能不可达或拒绝代理，因此不保证该示例必然成功。

`--noproxy "*"` 仅避免客户端到网关的连接受到本机代理环境干扰，并不是要求网关绕过所选代理。

需要选用 SOCKS5 上游时，在对应调用中增加：

```powershell
-H "X-Proxy-Proto: socks5"
```

**支持 SOCKS 出站，不代表客户端能把 `8916` 当作 SOCKS5 服务端。**

### 4.2 不同入口的边界

| 接入需求 | 当前情况 |
| --- | --- |
| 按 `Host` 契约发送普通 HTTP | 已有实现和历史公网闭环记录，适合作为首次验收。 |
| 项目 SDK | 可减少手工构造请求，仍要遵守各 SDK 的协议支持范围。 |
| 直接将 `8916` 设为标准 HTTP 代理 | 不应假定兼容，该入口主要使用项目请求契约。 |
| `tools/ipp_forward.py` | 转换标准 HTTP 代理请求；明确不转发 CONNECT。 |
| 独立 CONNECT listener 访问 HTTPS | 需配置 `CONNECT_ADDR`，明文只允许回环；有实现与本地测试，完整实网及生命周期验收仍待完成。 |
| 所有应用、UDP、QUIC 或整机流量 | 不属于当前已证明的通用能力。 |

HTTPS 目标访问与“网关到上游代理之间使用 TLS”也是两件事。后者不自动证明客户端到 HTTPS 目标的 CONNECT 已完整交付。

## 5. 实际使用范围与失败预期

### 5.1 适合开展的使用

- 本地实验、功能验证与自有程序接入。
- 对公开、无登录、非敏感网页的低流量访问。
- 观察免费供给、核对出口并验证错误处理。
- 在超时、有限重试、监控和停止条件明确时进行小规模试用。

不宜把免费线路作为必须连续可用的唯一出口，也不宜在未验收时依赖通用系统代理、长隧道、多实例计费或生产关停结算。

公开免费代理不是可信服务，不应用于支付、登录凭据或个人敏感数据。普通 HTTP 免费路径会拒绝部分携带 `Authorization`、`Cookie` 的请求；但这不代表 CONNECT 内的 TLS 数据也会被自动检查。

### 5.2 常见现象

| 现象 | 可能原因 |
| --- | --- |
| 免费池为零 | 源不可达、候选失效、筛选未通过，或尚未完成获取周期。 |
| 503 | 可能是未就绪、正在排空、无匹配节点或路径不可用，需查日志。 |
| 502、超时 | 可能是节点连接、上游协议或目标可达性问题。 |
| 403 | 可能是身份无效、免费线路凭据策略或目标拒绝，要区分响应来源。 |
| 429 / 402 | 可能触发租户限流或余额策略。 |
| HTTP 成功、HTTPS 失败 | HTTP 成功不能证明 CONNECT 已配置正确或上游支持隧道。 |
| 200 但出口不对 | 需排查本机代理干扰、透明代理、mock 或归因错误。 |

## 6. 与全球成熟同类产品的比较

### 6.1 应按产品类别对照

| 对象 | 类别 | 对本项目的参考意义 |
| --- | --- | --- |
| Envoy | 通用 L4/L7 数据面和动态控制面生态 | 动态配置、健康治理、可观测性与多实例配置管理。 |
| HAProxy | 成熟代理与负载均衡 | 健康检查、运行时治理和运维实践。 |
| Squid | HTTP 代理、缓存和访问控制 | 标准代理接入、认证与目标访问规则。 |
| Bright Data / Oxylabs | 商业代理网络服务 | 出口供给、地区与会话能力、客户服务和商业保障。 |

不建议给出“全球排名”或“达到顶级产品的百分之多少”。缺少统一测量方法时，这类数字会混淆功能数量与生产成熟度。

### 6.2 本项目的优势

- 出口供给、域名上下文选路、租户计量与健康治理组合较丰富。
- LinUCB、加权、粘滞与隔离具有明确实现，智能出口方向有辨识度。
- 自动测试、静态门禁、文档一致性及供应链治理已有基础。
- 执行记录能区分本地、mock、真实依赖和生产证据，便于追溯。

这些说明有继续演进的基础，不等于已经在相同条件下赢得性能或可靠性竞测。

### 6.3 主要差距

| 维度 | 当前差距 |
| --- | --- |
| 生产可靠性 | 当前版本完整生命周期、容量、长稳、HA、SLO 证据不足。 |
| 控制面 | 缺完整配置版本、发布、实例确认、漂移检测与回滚。 |
| 企业身份 | 静态 Key 不等于 OIDC/SSO、RBAC 和组织级权限。 |
| 账务 | 异步 Redis 运行态不等于审计账本，跨实例一致性未证明。 |
| 安全默认 | Compose 有开发占位凭据，生产弱凭据拒绝及统一出站策略待闭环。 |
| 协议 | 标准客户端、HTTPS 隧道和更多协议需独立验收。 |
| 出口资源 | 未自带商业级授权 IP 网络和 SLA。 |
| 策略效果 | 合成回放不能替代真实流量对照。 |

资源规模、授权和服务保障还依赖供给及运营，不能只靠路由算法补齐。

## 9. 当前部署的最小闭环验收建议

目标是证明现在的部署真实可用，不做大规模压测。

| 步骤 | 合格证据 |
| --- | --- |
| 固定版本与配置 | 记录 commit、入口、免费开关、协议及依赖状态，不记录秘密。 |
| 验证网关入口 | readiness 与依赖策略一致，数据面实际可接收请求。 |
| 验证免费供给 | 有抓取、验证、入池证据和适用节点。 |
| 强制免费路径 | 请求明确选择 free，协议与池内节点一致。 |
| 获取真实响应 | 取得有效状态和预期响应体，排除 mock 或代理错误页。 |
| 核验出口 | 目标回显与代理路径相符，排除直连、本机代理和透明转发等干扰。 |
| 交叉核对 | 服务端免费节点、状态及遥测可关联，启用数仓时进一步对账。 |
| 小批量重复 | 记录时段、尝试、成功、失败和延迟，不能只保留成功样本。 |
| 单独验收 HTTPS | 如有需求，另测 CONNECT、认证、客户端证书校验、内容及退出行为。 |

此表是待执行建议，不是通过记录。
